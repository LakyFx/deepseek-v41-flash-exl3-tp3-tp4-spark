# TensorFold TP4 4.0.4 - qualified B production recipe

4.0.4 is the **unchanged computational payload qualified as 4.0.4-B**.
The A compatibility/reliability baseline and B kernels are enabled. C's
alternative weight-read policy and D's file-cache advice are not enabled.
This is a selective backport, not an upgrade to the complete upstream engine.
The [4.0.3 Smart CUDA Graph Controller](DS41F-4.0.3.md), X4 Smart KV retention
and adaptive speculation are preserved.

## What changed

- **Long agent histories:** amortized string/list accumulation avoids repeatedly
  copying the whole prefix. Prompt bytes and token IDs stay identical. The
  1000-message CPU fixture reduced arena allocation from 229,049,041 to
  8,483,407 bytes. This is template allocation, not total RAM or a GPU speedup.
- **Thinking compatibility:** accept DeepSeek top-level booleans and enabled/
  disabled objects. Explicit template arguments retain their established
  priority. Image-bearing main routes retain the configured MAX policy.
- **Reported fatal CUDA errors:** remember a poisoned context and let a
  model-owned CPU supervisor terminate that rank for coordinated recovery.
  It does not treat a slow prefill/image as a failure or detect every silent hang.
- **Guarded EXL3 mid-M/WC kernels:** reuse decoded weight tiles on supported
  17-128-row singleton projections. Existing fused/grouped operations,
  incompatible shapes and unsupported shared-memory cases keep their original
  paths. The pre-existing split-K scratch-discard behavior is retained.
- **Internal JSON compatibility:** gateway-owned checkpoint/visual-note calls
  use an explicit JSON instruction plus strict schema/evidence validation
  and bounded retries. They previously requested grammar support unavailable
  in this native engine. Public caller response_format fields are preserved;
  constrained generation remains unsupported and returns an explicit error.

The three controllers make runtime decisions from measured history: graph
reuse/reconstruction costs, useful prefix returns, and speculative acceptance/
execution costs. They operate from the first request and keep adapting. There
is no fixed several-hour wait or guaranteed steadily increasing speed. This
does not train or alter the model weights.

## Stage without touching a running installation

Retain the [4.0.2 host/network, weights and Engram preparation](DS41F-4.0.2.md).
Verified balanced401a-v1 caches, two-way Engram, pinned patched NCCL,
tokenizer/template and the final prefill/AOT assets do not need rebuilding.
Choose new runtime directories; preserve your previous installation.

```sh
git clone https://github.com/LakyFx/deepseek-v41-flash-exl3-tp3-tp4-spark.git
cd deepseek-v41-flash-exl3-tp3-tp4-spark
git checkout v4.0.4
python3 tensorfold/extract.py --out /srv/ds41f-source-4.0.4
python3 -m tensorfold.tp4.v404.build \
  --kit /srv/ds41f-source-4.0.4/kit --out /srv/ds41f-tp4-4.0.4
```

The builder verifies/stages the five exact measured ARM64 executables, two
existing decode cubins, six additive cubins under `kit/cubins/`, and prefill
assets into a **new directory**. Nothing starts. Preserve these additive
cubins when completing the runtime's existing kit/model/rank-cache/Engram/RoPE
layout from the previous installation. Do not replace the populated kit with
an old kit that omits the new cubins. The launcher checks all six hashes.

Copy `tensorfold/tp4/cluster.example.json` to private operator configuration,
set all topology values and all four new runtime roots, then print commands:

```sh
python3 -m tensorfold.tp4.v404.launch --config /srv/cluster.local.json --rank 0
# During your maintenance window, on each respective node, rank 0 through 3:
python3 -m tensorfold.tp4.v404.launch --config /srv/cluster.local.json --rank 0 --run
```

Upgrade all four ranks together; preserve your all-rank readiness/recovery
barrier. Graph statistics default to `ROOT/state/smart-graphs/4.0.4-B.stats`;
the head launcher creates their parent. A separate namespace avoids inheriting
incompatible graph costs. Statistics are not saved executable CUDA handles.

Exact native source is reconstructed with the existing content-addressed path:

```sh
# Separate fresh extraction for an optional source rebuild, not the staged runtime:
python3 -m tensorfold.variants.build build --recipe v404 \
  --build-root /srv/ds41f-source-4.0.4 --out /srv/ds41f-rebuilt-4.0.4
```

A rebuild needs its own destination qualification. The new CUDA source,
reviewed donor files, licenses, measured cubins and ABI checker are in
`tensorfold/tp4/v404/kernels/` and `qualify_kernels.py`. Compile the generated
sources for sm_121 with CUDA 13.0.2, C++17, O3 and TF404_TRELLIS_NO_L1=0 or 1
as named; measured binaries remain the reference hashes. Do not substitute a
different kernel and claim it is the same qualified payload.

## Gateway

Install `./gateway` in its own environment as in [GATEWAY.md](GATEWAY.md).
Use `tensorfold/tp4/v404/gateway-profile.json` and `gateway.env.example`.
The matching profile enables the internal JSON contract; the portable entrypoint
also respects `LAGUNA_GATEWAY_TENSORFOLD_INTERNAL_JSON` as an explicit override.
Physical 9M KV and gateway 8M reserved-token admission are separate limits.

Retain your credentials, URLs, persistent vision DB and job revision namespace.
The 4.0.3 finite image-retention/accounting repair and durable agent-history
image path remain enabled. Image queue/job deadlines stay 1800/3590 seconds;
terminal payload retention is finite and active/unresolved jobs are protected.
The 4.0.3 gateway snapshot is retained in `gateway/history/4.0.3.tar.gz` for
historical audit; use its release tag for a complete older installation.
