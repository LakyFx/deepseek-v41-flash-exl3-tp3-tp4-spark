# TP4 4.0.7

This is the four-Spark production release for DeepSeek-V4.1-Flash-1017. It ships the measured ARM64 runtime, the compact sampling and ragged prefill kernels, and the DeepSeek gateway update. The existing balanced401a-v1 EXL3 shards, two-way Engram layout, 9M KV positions and C16 capacity carry over from 4.0.5.

## Runtime and gateway changes

- The speculation controller accounts for concurrent streams, draft origin and the measured cost of the next token. It refreshes depth estimates and can revoke a choice that slows decoding.
- Whole-prompt prefill reuses routing weights and prompt metadata. The launcher selects the matching ragged prefill and compact sampling kernels on all four ranks. Prefill pipelining is disabled.
- Under context pressure, the gateway preserves user instructions and their evidence through Chat and Responses compaction. It budgets the internal output against the remaining context and retries an invalid evidence reference. HTTP regression cases cover histories with 5, 12 and 37 rules.

## Upgrade from 4.0.5

Use the same four-Spark [weights, rank caches, Engram partitions and patched NCCL prerequisites](DS41F-4.0.4.md). Preserve your private topology, gateway credentials and vision job database. Stage 4.0.7 in a fresh runtime directory on each rank.

```sh
git fetch origin tag v4.0.7
git checkout v4.0.7
python3 tensorfold/extract.py --out /srv/ds41f-inputs-4.0.7
python3 -m tensorfold.tp4.v407.build \
  --kit /srv/ds41f-inputs-4.0.7/kit --out /srv/ds41f-tp4-4.0.7
```

Complete the kit and the model, rank-cache and Engram paths in each new runtime as in the [TP4 installation guide](DS41F-4.0.4.md). For an upgrade, copy or link the existing model and weight directories. Keep the six packaged kit cubins when completing the kit. Set each rank's `root` in your private cluster configuration to its new runtime. Print the four commands to check paths and topology.

```sh
for rank in 0 1 2 3; do
  python3 -m tensorfold.tp4.v407.launch --config /srv/cluster.local.json --rank "$rank"
done
```

During your maintenance window, start each rank on its own machine using its rank number and `--run` with the same config. Switch the four ranks together using your existing readiness barrier. Rank 0 defaults to `state/smart-graphs/4.0.7.stats` under the new runtime.

Install the gateway in its existing Python environment with `python3 -m pip install --upgrade ./gateway`. Use the [4.0.7 gateway environment](../tensorfold/tp4/v407/gateway.env.example) and [TP4 profile](../tensorfold/tp4/v407/gateway-profile.json), then restart your gateway during your chosen window. TP3 users can still select the explicit [1.3.0 profile](../tensorfold/tp3/v130/gateway-profile.json).

The [prefill CUDA source and compiler flags](../tensorfold/tp4/v407/kernels) accompany the shipped cubin. The [native source recipe](../tensorfold/variants/recipes/v407.json), [runtime profile](../tensorfold/tp4/v407/profile.json) and [payload hashes](../tensorfold/tp4/v407/PAYLOAD.json) identify the shipped build. To reconstruct just the production source on Linux, run `python3 -m tensorfold.variants.build build --recipe v407 --prepare-only --build-root /srv/ds41f-inputs-4.0.7 --out /srv/ds41f-rebuilt-4.0.7` immediately after a clean extraction.
