# TensorFold TP4 4.0.3 — stability and bounded memory

**Current qualified production release.** This adds the Smart CUDA Graph
Controller and repairs vision payload retention/admission to 4.0.2. The
Smart KV cache controller, Smart Adaptive speculation, balanced weights,
sampling and transport remain unchanged. Previous recipes remain available.

| Setting | Value |
| --- | --- |
| Model / topology | DeepSeek-V4.1-Flash-1017, mixed EXL3 ~3.51 bpw, switchless TP4 |
| Capacity / speculation | C16 / adaptive shared R48, maximum five draft tokens |
| KV / checkpoints | 9,000,000 positions / 3.5 GiB on the head |
| Prefill / physical KV quantum | 8192 / 2048 tokens |
| Context / weight layout | 401408 / unchanged `balanced401a-v1` |
| Graph memory reserve | 1024 MiB on the tightest rank; soft target |
| Graph metadata / poll | 1024 groups / every 128 controller boundaries |
| Vision | Two concurrent jobs, MAX, 8192 reasoning + 32768 final headroom |
| Source | `v403`, revision `6af7a7ca07be7def6f8e63c60e6ee15291fae949` |

## What was repaired

- **Smart CUDA Graph Controller:** share graph body work across greedy and
  sampling heads; agree capture admission and retirement across all ranks.
  Bounded recency/return and measured reconstruction costs protect useful
  graphs. Under memory pressure, retire selected cold graph groups rather
  than periodically clearing the cache. Preserve captured buffer ownership.
  Destruction failures fail closed; never continue with mismatched ranks.
- **Useful telemetry and persistence:** log hits, captures, retirement and
  memory recovery; write compatible bounded statistics asynchronously. The
  statistics file does not preserve executable CUDA handles across restarts.
  Capture/maintenance time is excluded from speculative cost learning, while
  acceptance feedback is retained.
- **Bounded HTTP memory:** retain at most 16 MiB of temporary arena capacity
  per connection between requests, rather than each connection's largest
  historical allocation. This does not shrink model/KV buffers.
- **Vision storage:** use consistent UTF-8 payload/reservation accounting at
  admission and dispatch. Terminal image bodies expire one hour after the
  later of the original deadline and last update. Result/delivery records
  remain available for seven days. Never expire active or unresolved attempts.
  SQLite reuses freed pages; a large physical DB file is not active image data.
- **Agent image turns:** Chat, Responses, standalone jobs and image-bearing
  agent/tool history use the same durable controls and MAX/8K/32K profile.
  Preserve complete text and tool-call outputs, finite deadlines and verified
  cancellation before a bounded repair. Keep the existing logical job namespace.
- **ARM64 compatibility:** the asynchronous statistics worker uses the standard
  worker stack. The published binaries include this production correction.

## Install without changing an existing deployment

Preserve the [4.0.2 host, network, weight and Engram preparation](DS41F-4.0.2.md).
The balanced rank-cache bytes and receipts, two-way Engram, pinned patched NCCL,
model metadata, tokenizer/template, RoPE and final CUDA assets are unchanged.
Already verified balanced caches need no repacking. Arrange these inputs under
each new runtime root; reuse read-only directories through operator-managed
mounts if desired. Do not replace running files or use old unbalanced caches.

```sh
git clone https://github.com/LakyFx/deepseek-v41-flash-exl3-tp3-tp4-spark.git
cd deepseek-v41-flash-exl3-tp3-tp4-spark
git checkout v4.0.3
python3 tensorfold/extract.py --out /srv/ds41f-source-4.0.3
python3 -m tensorfold.tp4.v403.build \
  --kit /srv/ds41f-source-4.0.3/kit --out /srv/ds41f-tp4-4.0.3
```

This verifies and stages the measured ARM64 head/follower/check executables,
unchanged plan/load tools and CUDA assets into a NEW directory. Nothing starts.
Exact source is reconstructed by the existing content-addressed mechanism:

```sh
# Use a separate fresh source extraction for an optional rebuild:
python3 -m tensorfold.variants.build build --recipe v403 \
  --build-root /srv/ds41f-source-4.0.3 --out /srv/ds41f-rebuilt-4.0.3
```

Rebuilt binaries need their own host qualification. To use the already measured
payload, use `tensorfold.tp4.v403.build` above. Additional unchanged kernel source
and balanced-cache verification tools remain in `tensorfold/tp4/v402/`.

Copy `tensorfold/tp4/cluster.example.json` to private configuration. Replace
topology placeholders and set every rank's root to its new runtime. The launcher
defaults graph statistics to `ROOT/state/smart-graphs/4.0.3.stats`; optionally set
`graph_statistics_path` in your private cluster JSON to an operator-owned path.
The rank-0 `--run` launcher creates its statistics parent before starting.

```sh
# Print the complete command first; no inference or service action:
python3 -m tensorfold.tp4.v403.launch --config /srv/cluster.local.json --rank 0
# During your maintenance window, on each corresponding node, ranks 0..3:
python3 -m tensorfold.tp4.v403.launch --config /srv/cluster.local.json --rank 0 --run
```

**Upgrade the head and all three followers together.** The graph controller
changes the collective protocol; mixed 4.0.2/4.0.3 ranks are unsupported.
Preserve the all-four-node startup/recovery barrier and old installation for
rollback. Reopening ingress requires all four ranks healthy. Publication does
not restart or install services on your machines.

## Gateway upgrade

Install `./gateway` in the gateway's own environment as described in
[GATEWAY.md](GATEWAY.md), then use `tensorfold/tp4/v403/gateway-profile.json`
and `gateway.env.example` from that same directory. This explicit profile
selects TP4 C16 and the existing 8M admission limit; the legacy default TP3
profile is preserved for older installations.
The physical KV pool remains 9M; these are different limits.

Keep your API key, URLs, persistent vision DB, job revision namespace and private
state. Rehearse the additive SQLite upgrade on a consistent backup first; stop
the gateway for a consistent migration/rollback. The existing 4.0.2 recovery
rollback inspector remains available. Do not delete unresolved attempts or
redownload images merely because an HTTP client disconnected.

Vision queue/job deadlines remain 1800/3590 seconds. Retention housekeeping
does not run blocking VACUUM or change generation budgets. This release does
not implement constrained JSON decoding: native `response_format`/`guided_*`
requests can still return HTTP 400, as they did before 4.0.3. Do not claim an
enforced schema by silently deleting those fields.
