# TensorFold TP4 4.0.5 — image-cache and JSON compatibility

4.0.5 is the exact tested and owner-approved production successor to [4.0.4](DS41F-4.0.4.md).
It preserves the qualified B compute path, weights, transport and algorithms of
all three smart controllers. It selectively integrates the image-aware cache
fix from [hteak's issue #2](https://github.com/LakyFx/deepseek-v41-flash-exl3-tp3-tp4-spark/issues/2)
and the JSON gateway qualified with [TP3 1.3.0](DS41F-1.3.0.md).

## What changed

Image-bearing histories now carry content-derived image identities through
prompt construction and cache matching. Repeating the same image can reuse
the valid prefix; replacing an image invalidates reuse at that image boundary.
Checks cover Chat, Responses, one and two images, warm reuse and replacement.
Image row restoration is bounded by the established namespace/history rules.
This does not correct contradictory earlier descriptions supplied by a client.

Explicit JSON object/schema/guided requests are normalized and validated by
the CPU gateway, with bounded validation workers and at most one correction.
Tool intermediate messages and streaming/Responses behavior have separate
regressions. Unsupported schemas or unresolved invalid answers return explicit
errors. This is not native grammar-constrained decoding or a universal answer
success guarantee. The native inference geometry and sampling are unchanged.

Source differs from 4.0.4 in eight files: image-key/prompt/host interfaces and
tests plus a new graph build fingerprint. The three controller algorithms,
B kernels and balanced weight shards remain byte-identical. A fresh versioned
statistics namespace avoids mixing graph costs from different executables.

## Stage and launch

Retain the [4.0.4 host/network/weight/Engram prerequisites](DS41F-4.0.4.md).
There is no automatic live upgrade. Choose new runtime directories and preserve
the old release, private cluster configuration, learner statistics, credentials
and durable vision database. Upgrade all four native ranks together.

```sh
git clone https://github.com/LakyFx/deepseek-v41-flash-exl3-tp3-tp4-spark.git
cd deepseek-v41-flash-exl3-tp3-tp4-spark
git checkout v 4.0.5
python3 tensorfold/extract.py --out /srv/ds41f-source-4.0.5
python3 -m tensorfold.tp4.v405.build   --kit /srv/ds41f-source-4.0.5/kit --out /srv/ds41f-tp4-4.0.5
```

The offline stager verifies and installs the three newly compiled measured
ARM64 executables plus unchanged plan/load support tools, two existing decode
cubins, all six B kit cubins and the isolated TP4 prefill/AOT set. Complete the
kit/model/balanced rank-cache/Engram/RoPE layout as described in 4.0.4. Do not
overwrite the new kit with an older one missing the six B cubins. Use the same
patched NCCL build and four explicitly ordered ranks.

Copy `tensorfold/tp4/cluster.example.json` to private operator configuration,
fill topology values and all four runtime roots, then print each command:

```sh
python3 -m tensorfold.tp4.v405.launch --config /srv/cluster.local.json --rank 0
# During an operator-approved maintenance window, each respective rank 0..3:
python3 -m tensorfold.tp4.v405.launch --config /srv/cluster.local.json --rank 0 --run
```

Retain the existing all-four-node readiness and coordinated recovery barrier;
change its explicit executable/launcher paths to this release together. Rank 0
creates the writable graph-statistics parent; default is
`ROOT/state/smart-graphs/4.0.5.stats`. No in-memory CUDA handles or KV are imported
from another release. The launcher never replaces an existing service.

For optional source reconstruction/rebuild, use a separate clean extraction:

```sh
python3 -m tensorfold.variants.build build --recipe v405   --build-root /srv/ds41f-source-4.0.5 --out /srv/ds41f-rebuilt-4.0.5
```

Rebuilt payloads need destination qualification. The published measured
executables remain the reference. Unchanged CUDA sources, six cubins, donor
licenses, compile flags and ABI checker stay in `tensorfold/tp4/v404/kernels/`
and `tensorfold/tp4/v404/qualify_kernels.py`; do not rebuild/replace them merely
to install 4.0.5. Original image patch and credits are in the v405 folder.

## Gateway

Install `./gateway` in an independent environment per [GATEWAY.md](GATEWAY.md).
Use [v405/gateway-profile.json](../tensorfold/tp4/v405/gateway-profile.json) and
[gateway.env.example](../tensorfold/tp4/v405/gateway.env.example). Current package
defaults are TP4 C16; TP3 users explicitly select the v130 profile and version.
Install the pinned JSON dependencies. Preserve the durable job DB and its
namespace; do not restore an old DB over newer jobs. Keep the existing MAX
policy for dedicated vision and image-bearing agent histories, C2 and finite
queue/run/cancellation deadlines. Images are not a reason to change native
sampling or bypass admission/cancellation accounting.

Shared gateway modules match qualified 1.3.0; only the portable version/capacity
defaults and explicit operator address adaptations differ. The frozen 1.3.0 and
4.0.4 gateway snapshots remain in `gateway/history/` for historical audits.

## Evidence and limits

[Full benchmark report](BENCHMARK-4.0.5.md) and
[numeric evidence](../results/20261104-4.0.5) retain all 3 fast passes, cold 64K,
both C1-C16 heavy passes, failure counts, full-concurrency samples, five-depth
speculation and image/JSON/memory checks. Heavy 135/136 on each pass; no failed
tasks were removed or replayed. The first pass had a control pause before its
previously unattempted C16 wave. Minimum sampled free memory was 9.66 GiB and
native/cgroup swap stayed 0 during the measured post-ready window; this is not
a 24-hour or full 9M pressure qualification.

The new flyer uses whole TP4 pass 2 for both panels. Fast numbers sum individual
request decode rates; heavy numbers are medians of the rolling 2s native total
only while all C tasks stream throughout that window, with 0.5s margins.
Per-task heavy is the concurrent average, total/C, from those same samples.
Whole-wave throughput and request medians are retained separately. TP3 flyer
short data is 1.2.9 native; its heavy data is explicitly historical 1.2.5/K2a,
not a freshly measured 1.3.0 heavy run. Older evidence remains unchanged.
